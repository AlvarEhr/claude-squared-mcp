# claude-pair-mcp — design plan

A local MCP server that exposes long-running Claude Code CLI sub-sessions as addressable "pairs", giving the calling session true recursion (child can spawn its own sub-agents), persistent context across turns, and per-pair specialization.

## Verified capability matrix (from validation tests)

| Capability | Status | Notes |
|---|---|---|
| Headless one-shot (`--print`) | ✅ | Returns JSON with `session_id`, `result`, `permission_denials`, `total_cost_usd` |
| Resume-by-UUID (`--resume <uuid>`) | ✅ | Preserves full context, all tools, all deferred tools |
| Pre-assigned UUID (`--session-id <uuid>`) | ✅ | No output parsing needed |
| Child can use `Agent` tool (recursion) | ✅ | Sonnet child spawned Haiku sub-agent successfully |
| `--strict-mcp-config '{"mcpServers":{}}'` disables MCPs | ✅ | Drops to 31 built-in tools (incl. SendMessage, TeamCreate) |
| `--append-system-prompt` persists across resume | ✅ | Set ONCE at creation, no re-pass on resume |
| `--allowed-tools` persists across resume | ✅ | Same pattern as system prompt |
| `--model` persists across resume | ❌ | **Must re-pass every call** — else falls to settings.json default |
| `--permission-mode auto` works in child | ✅ | Gated PowerShell calls correctly; child pivoted to working alternative |
| Stream-json multi-turn (single process) | ✅ | Same session reused, cache hits on turn 2 (36k tokens cached) |
| `permission_denials` surfaced in JSON | ✅ | Array of {tool_name, tool_input} per denial |
| Stable session_id across resumes | ✅ | Same UUID returned every call |
| Gemini parity | ⚠️ | Resume is by INDEX not UUID; `--session-id` only sets new UUIDs. Adapter is harder. |

## Design decisions

| Question | Decision | Rationale |
|---|---|---|
| Language | **Python 3.11 + FastMCP** | Python already installed; FastMCP recommended by mcp-builder skill; faster to dev |
| Transport | **stdio** | Local server; matches skill recommendation |
| Backend | **Claude only in v1; Gemini deferred** | Gemini's index-based resume needs more design work |
| Operating mode | **Option B (resume-per-call) for v1** | Stateless, no zombie processes; ~2-4s overhead acceptable. Option A (long-running stream-json) available as `pair_persist(name)` upgrade later |
| MCPs in child | **Disabled by default** via `--strict-mcp-config '{"mcpServers":{}}'`; opt-in via `mcp_whitelist` param at create | Token bloat avoided; per user preference |
| Specialization | **Pin at create** (`--append-system-prompt`, `--allowed-tools`, `--strict-mcp-config`, `--cwd`) | Verified to persist; saves repeated CLI args |
| Per-call args | **`--model`, `--permission-mode`** re-passed from registry every call | `--model` doesn't persist; permission-mode might also vary |
| Registry | `~/.claude/pairs/registry.json` with `filelock` | Single file, atomic writes, cross-process safety |
| UUID strategy | **Pre-assign via `--session-id`** at create | No race conditions; registry seeds the UUID |
| Auto-mode safety | **Mandatory `--permission-mode auto`** for v1 | No `--dangerously-skip-permissions` option in API; `acceptEdits` available as override but only `auto` by default |
| Default model | **opus** (matches user's main session) | User on Max 5x plan, cost not a concern |

## Tool API (FastMCP `@mcp.tool` registrations)

All tools namespace as `pair_*`. Names follow skill recommendation: action-oriented, consistent prefix.

```python
# Create a new pair
pair_create(
    name: str,                                    # unique addressable name
    purpose: str,                                 # human-readable description (stored, not used by CLI)
    model: str = "opus",                          # alias or full model name
    system_prompt_append: Optional[str] = None,   # specialization (pinned)
    allowed_tools: Optional[List[str]] = None,    # tool allowlist patterns, e.g. ["Bash(git *)", "Read", "Edit"]
    mcp_whitelist: Optional[List[str]] = None,    # MCP server names to enable; default = none
    cwd: Optional[str] = None,                    # working dir for the pair; default = current
    permission_mode: str = "auto",                # auto | acceptEdits | plan | default
    initial_message: Optional[str] = None,        # if set, sends it as the first turn and returns response
) -> {
    name: str, session_id: str, status: "ready",
    transcript_path: str,                          # ~/.claude/projects/<cwd-encoded>/<uuid>.jsonl
    initial_response: Optional[str],
}

# Send a message and get response (sync, blocks until child completes)
pair_send(
    name: str,
    message: str,
    timeout_seconds: int = 300,
    override_model: Optional[str] = None,         # one-call model override
) -> {
    response: str,                                 # the `result` field from CLI JSON
    permission_denials: List[dict],                # what auto-mode blocked
    cost_usd: float,
    duration_ms: int,
    session_id: str,
    model_used: str,
    cache_hit_tokens: int,
    needs_action: Optional[str],                   # from post_turn_summary if child stopped expecting input
}

# Read registry
pair_list() -> { pairs: [{name, purpose, model, session_id, last_active_at, ...}] }

# Get one pair's full details
pair_info(name: str) -> {
    name, purpose, model, session_id, system_prompt_append,
    allowed_tools, mcp_whitelist, cwd, permission_mode,
    created_at, last_active_at, transcript_path, transcript_exists: bool,
    turn_count: int, total_cost_usd: float
}

# Tail recent turns from the pair's JSONL transcript
pair_transcript(name: str, last_n: int = 10) -> {
    turns: [{role: "user"|"assistant", content: str, timestamp: str, tool_uses?: [...]}]
}

# Update mutable settings (model, permission_mode, allowed_tools can all change per-call basis)
pair_update(name: str, model?, permission_mode?, allowed_tools?, purpose?) -> {ok: true}

# Remove from registry; optionally archive the transcript
pair_forget(name: str, archive: bool = True) -> {ok: true, archived_to?: str}
```

### Why no `pair_kill` / `pair_stop`

Option B (resume-per-call) means there's no long-running process to kill. Each `pair_send` is a fresh `claude --print` invocation that exits. The "pair" exists as a registry entry pointing to a stored session.

### Future: async variant

```python
pair_send_async(name, message) -> {task_id, started_at}
pair_poll(task_id) -> {status: "running"|"done"|"failed", response?, ...}
```

Useful when the calling session wants to fan out to multiple pairs without serializing. Defer to v1.1.

### Adapter trait (for future Gemini support)

```python
class PairAdapter(ABC):
    @abstractmethod
    def create(self, spec: PairSpec) -> CreateResult: ...

    @abstractmethod
    def send(self, spec: PairSpec, message: str, model: str, permission_mode: str,
             timeout: int) -> SendResult: ...

    @abstractmethod
    def transcript_path(self, spec: PairSpec) -> Path: ...
```

`ClaudeAdapter.send` shell-outs to: `claude --print --resume <uuid> --model <m> --permission-mode <pm> --output-format json -p "<msg>" < nul`

## Implementation steps

1. **Scaffold** the project: `~/code/claude-pair-mcp/`. Initialize with `uv init` or `pip install -e .`
2. **Install deps**: `pip install fastmcp filelock pydantic`
3. **Write `models.py`**: Pydantic for `PairSpec`, `CreateResult`, `SendResult`, registry shape
4. **Write `registry.py`**: load/save with `filelock`, atomic rename pattern
5. **Write `adapters/claude.py`**: shell-out wrapper. Critical bits:
   - Pre-assigned UUID via `--session-id` on create
   - `< NUL` on Windows (or `< /dev/null`) to avoid 3s stdin wait
   - Parse stdout JSON for `result`, `session_id`, `permission_denials`, `total_cost_usd`, `duration_ms`
   - On create: also pass `--append-system-prompt`, `--allowed-tools`, `--strict-mcp-config`, `--cwd`
   - On send: only `--resume`, `--model`, `--permission-mode`, `-p`
6. **Write `server.py`**: FastMCP instance, register each tool with input/output schemas
7. **Local test**: `python -m claude_pair_mcp` + run with MCP Inspector (`npx @modelcontextprotocol/inspector`)
8. **Register with Claude Code**: `claude mcp add pair --transport stdio -- python -m claude_pair_mcp`
9. **Verify in a fresh Claude session**: should see `mcp__pair__create`, `mcp__pair__send`, etc.
10. **Eval suite (per skill phase 4)**: 5-10 XML eval questions exercising the pair API

Estimated effort: **2-4 hours** for v1 (no Gemini, no async, no transcript tailing). Plus 1 hour for evals.

## Risks / open questions

1. **Concurrent registry access from multiple Claude Code sessions.** Mitigated by `filelock`; not perfect under heavy fan-out but fine for normal use.
2. **Session JSONL orphans.** If user wipes `~/.claude/projects/` the session_id is dead. `pair_info` should detect and offer to recreate.
3. **Auto-mode classifier divergence.** The child runs with its own auto-mode rules from the user's settings, not ours. Document but don't override.
4. **Token budget.** No hard cap by default. Consider per-pair `max_total_cost_usd` field for safety.
5. **Gemini adapter design.** Open. Likely needs: store Gemini's session index in registry, refresh via `gemini --list-sessions` before each resume. Defer to v1.1.
6. **Plan-mode interplay.** If a pair is created with `permission_mode: "plan"`, sends must be aware they can't write. Document.
7. **The `--brief` flag enables a `SendUserMessage` tool** in the child for agent-to-user comms. Interesting but unused in v1.
8. **CCD harness vs vanilla Claude Code.** The MCP works in either, but this current session is CCD — installing the MCP here may or may not surface tools, depending on how CCD discovers MCPs. Test in a vanilla `claude` shell to confirm.

## Skill alignment (anthropic-skills:mcp-builder)

- ✅ Tool naming: `pair_*` prefix, action-oriented (create, send, list, info, forget, update, transcript)
- ✅ Output schemas: Pydantic models with `structuredContent`
- ✅ Annotations: `pair_send` → `readOnlyHint:false, destructiveHint:false, idempotentHint:false`; `pair_forget` → `destructiveHint:true`; `pair_list/info/transcript` → `readOnlyHint:true`
- ✅ Actionable errors: e.g., "Session UUID xxx not found in ~/.claude/projects/. Run pair_forget then pair_create to reset."
- ✅ Pagination: `pair_transcript(last_n=10)` keeps responses bounded
- ✅ Transport: stdio per recommendation
- ✅ Phase 4 evals: write 5-10 XML qa_pairs covering create+send round-trip, recursion proof, denial recovery, registry persistence

## Configuration the user controls

After scaffolding, user can:
- Edit `~/.claude/pairs/registry.json` directly to retire pairs, rename, change models
- Set `~/.claude/pairs/profiles/<name>.md` with `--system-prompt` content (loaded if `pair_create` references it by filename)
- Disable the MCP entirely via `claude mcp disable pair`
